# Brian and Jenna Packet

## One sentence

Santa Fe Brewing already has the brand, spaces, beer, photos, and people. The opportunity is to reduce friction around updating, coordinating, securing, and operating all of it.

## What was built quickly

A static-first demo with deeper page structure:

- Homepage
- Beer/cider archive model
- Locations and venue template model
- Events and concerts workflow
- Jenna-facing media workflow
- Brew-ops pilot page
- HTTPS/security posture
- Client-facing packet page
- Lighthouse/static QA report set

## Why this matters

The current team appears media-strong but time-constrained. That is common: great photographers and media people get trapped doing repetitive web operations. The system should let them upload strong assets and approve good drafts, not rebuild the same web/event/social copy again and again.

## Practical business value

1. Faster public updates.
2. Cleaner venue and event pages.
3. Better reuse of existing photography.
4. Less repeated copywriting for Jenna.
5. Shared manager cockpit instead of scattered laptops and spreadsheets.
6. Warehouse slotting based on movement patterns.
7. Lighting/glare measurement at the long bar.
8. BrewOS protection through backup, isolation, virtualization planning, and reporting augmentation.

## Security posture

The demo deliberately avoids payment handling and POS replacement. BrewOS should be protected, not attacked. First steps should be backup, isolation, virtualization planning, reporting augmentation, and PCI boundary review.

## Operations posture

Start small:

- Warehouse slotting based on product movement.
- Lighting/glare measurement at the long bar.
- Raspberry Pi sensor node for environmental logging.
- Manager cockpit for daily handoff and repeated spreadsheet tasks.

## Plain-English ask

Pick one annoying workflow that matters. We clean that first.
